# ЛАБОРАТОРНАЯ РАБОТА «БАНКОВСКАЯ СИСТЕМА»

## Цель работы
Закрепить навыки объектно-ориентированного проектирования, работы с исключениями, обработки пользовательского ввода, а также освоить базовый процесс совместной разработки через Git и GitHub.

## Часть 1. Техническое задание

### Описание сущностей

Необходимо разработать классы для моделирования банковской системы:

- **Клиент (Client):** хранит уникальный ID, ФИО и список своих счетов.
- **Счет (Account):** хранит уникальный номер счета (генерируется автоматически при создании), ID владельца, валюту (например, RUB, USD, EUR) и текущий баланс.
- **Банк (Bank):** выступает в роли фасада/менеджера. Хранит список всех клиентов и их счетов, предоставляет методы для взаимодействия с ними.

### Бизнес-логика и методы

Реализуйте следующие операции:

1. **Регистрация клиента** (создание нового клиента в банке).
2. **Открытие счета:** клиент может иметь несколько счетов, но строго только один счет в каждой валюте.
3. **Закрытие счета:** счет можно закрыть только если его баланс равен нулю.
4. **Пополнение счета:** увеличение баланса на указанную сумму.
5. **Снятие средств:** уменьшение баланса. Снять больше, чем есть на счету, нельзя.
6. **Перевод между счетами:** перевод возможен только между счетами в одной валюте. Переводить самому себе или несуществующему клиенту нельзя.

### Обработка исключений

Вместо стандартных ошибок Python используйте кастомные исключения для нештатных ситуаций. Минимальный набор:

- `InsufficientFundsError` — недостаточно средств для снятия/перевода.
- `AccountNotFoundError` — счет или клиент не найден.
- `CurrencyMismatchError` — попытка перевести средства между счетами разных валют.
- `DuplicateCurrencyError` — попытка открыть второй счет в той же валюте.
- `AccountNotEmptyError` — попытка закрыть счет с ненулевым балансом.

### Терминальный интерфейс (CLI)

Реализуйте консольное меню на базе цикла `while True`.

- При запуске программа запрашивает ID клиента. Если клиент не найден, предлагает создать нового.
- После успешного входа клиенту доступно меню: просмотр своих счетов, пополнение, снятие, перевод, формирование выписки, выход.
- **Важное требование:** Интерфейс должен быть устойчив к ошибкам пользователя. Если пользователь вводит буквы вместо цифр, отрицательные суммы или несуществующие номера счетов, программа не должна падать с traceback. Необходимо перехватывать ошибки и вежливо просить ввести данные корректно.

### Формирование выписки

Реализуйте функцию сохранения выписки по всем счетам клиента. Информация должна сохраняться в файл (например, `statement_<ID>.txt` или `.csv`). Файл должен содержать:

- Дату и время генерации.
- Список счетов (номер, валюта, текущий баланс).
- Итоговый баланс по каждой валюте.

## Часть 2. Порядок сдачи работы (Git и GitHub)

**Внимание!** Прямая загрузка (push) кода в главную ветку (`main`) запрещена настройками репозитория. Работа сдается через ваши отдельные ветки

### Шпаргалка по Git

**1. Подготовка**
```bash
# Клонируйте репозиторий на свой компьютер
git clone <ссылка_на_этот_репозиторий>
cd <название_папки>

# Создайте свою личную ветку и перейдите в неё (замените фамилию на свою)
git checkout -b feature/<фамилия>
```
**2. Фиксация изменений (Коммит)**
```bash
# Добавьте все измененные файлы
git add .

# Сделайте коммит с понятным описанием
git commit -m "Реализованы классы Bank, Client, Account и меню"
```
**3. Отправка на GitHub**
```bash
# Запушьте вашу ветку на сервер
git push origin feature/<фамилия>
```
